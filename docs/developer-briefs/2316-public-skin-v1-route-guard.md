# #2316 — Production Skin V1 Route Guard

## Human evidence

Opening `https://plotpickle.com/skin-v1` on the public custom domain renders the internal PlotPickle LOGON shell and stops at **LOGON UNAVAILABLE**.

The screen is generated by PlotPickle itself. The Skin V1 client calls `/api/auth/profile`; the public Sites deployment is not the local/server application runtime that owns profile authentication, so the client correctly fails closed.

## Root cause

The #2262 public-site worker rewrites the production custom-domain root to `/site`, but non-root application routes still pass through to the application router. As a result, a direct request for `/skin-v1` can enter the local application shell on the public website.

This is a route-boundary defect, not a credential or browser-session defect.

## Decision

Guard only the observed Skin V1 application namespace on the production custom domain.

- `plotpickle.com/skin-v1`
- `plotpickle.com/skin-v1/*`

These routes receive a temporary HTTP 307 redirect to `https://plotpickle.com/`.

A temporary redirect is deliberate because PlotPickle may later choose to publish an authenticated application runtime. The current pre-release website must not permanently cache that policy.

## Preserved boundaries

- localhost and loopback `/skin-v1` remain unchanged;
- WebMCP continues to use the local/private Skin V1 application;
- profile/auth implementation is unchanged;
- the existing ChatGPT Sites project and custom domain are unchanged;
- the public homepage, Blog, discovery endpoints and provenance model are unchanged;
- no public authentication backend is introduced.

## Verification

The existing #2262 public-site authority regression now also verifies the production-only Skin V1 redirect contract.

Exact-head Architecture Verification remains the merge authority.

After merge and Sites deployment, verify:

1. `https://plotpickle.com/` renders the public site.
2. `https://plotpickle.com/skin-v1` resolves back to the public homepage.
3. a nested `/skin-v1/... ` request also resolves back to the public homepage.
4. local/WebMCP `/skin-v1` remains available.
