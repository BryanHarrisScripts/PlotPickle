# Candidate package contract

The host creates one package per project, exact PPF revision, and canonical character. Each study remains independently addressable and versioned.

Required package evidence:

- package ID and version;
- project ID and exact PPF base revision;
- canonical character ID, name, and role;
- canonical PPF evidence references;
- approved visual identity references;
- observed/inspiration references;
- provider, runtime, model, consent, and cost state;
- invoking authority class and bounded autonomous run ID when applicable;
- created timestamp, review state, consistency findings, and accepted artifact ID when linked by the host.

Required study evidence:

- study ID, type, and version;
- source and dependency references;
- approved, observed, and generated candidate references kept separately;
- provider/runtime/model;
- safe specification fingerprint, seed, and settings when available;
- parent candidate/version when revised;
- concrete consistency findings;
- candidate review state;
- stale state, reason, and exact changed evidence references;
- accepted artifact ID only after the host verifies existing acceptance evidence.

Do not include prompts containing unnecessary private story text, credentials, hidden chain-of-thought, raw model deliberation, or unbounded provider output.

The reference-board study should identify the provenance and role of each item. Other studies should cover the requested turnaround angles, canonical emotional performance, movement language, wardrobe/prop continuity, applicable powers/effects, palette/material rules, and interaction with canonical environments. Missing canon should remain visibly missing or open; generation is not permission to fill canon silently.
