# PP-AFTERGLOW-CONSOLIDATE-001 — Every User's Afterglow Consolidation Truth

**Status:** Human-directed, implementation in phases under issue #2863. Phase 1 planner is review-only; no profile mutation or example publication.

## Governing Human Truth

**Every authenticated PlotPickle user** must be able to consolidate **every saved working version of their own Afterglow**, regardless of how many exist, across all supported durable project fields into **one current, authoritative Afterglow for that account**. No valid earlier change may disappear merely because another working copy is newer. The confirmed consolidated result replaces all superseded working copies as the account's normal **Open Afterglow / Continue Current** entry. Earlier copies remain recoverable history, not parallel active versions. The shared **provided/packaged example distributed to other users** is distinct: making a private account's consolidated project public requires a separate, explicit and authorized promotion/release action. A merge must never silently publish anyone's private work.

## Rules and proof obligations

- **TRUTH 1 — All durable fields:** Enumerate the canonical project schema, not selected screen labels. Preserve Foundations, World, Mind Map accepted storyDevelopment fields and Mind Map notes, Build artifacts/locks, Production, Structure, Writing, Discovery, World Map, mutable screenplay evidence, and every other supported durable project field. New schema fields require an explicit adoption review; quietly omitting them from promotion is failure.
- **TRUTH 2 — Universal, account-scoped authority:** The same capability and contract apply to **any signed-in user**, not one named developer or administrative account. Each consolidation reads only that user's verified, currently hydrated, owned Afterglow working versions. No cross-account merge, private-data exposure, automatic startup import or foreign-account reconciliation. This grants every user authority over **their own current Afterglow**, not automatic authority to overwrite the publicly packaged example.
- **TRUTH 3 — Unbounded set of versions:** For **any finite number N >= 1** of the current user's saved Afterglow working versions, compare each complete snapshot against the trusted common Afterglow baseline, preserving immutable `afterglow-v9-complete-baseline` provenance. N is discovered at execution, **never** fixed at 3 or 4; a later fifth, sixth or fiftieth copy must be included by the same rule. Saved versions are snapshots, **not** assumed incremental patches, and the newest is not proof that it contains older edits. All approved changes must either be present in the candidate or explicitly represented as a reviewable conflict.
- **TRUTH 4 — Question-first reconciliation, not repeated approvals:** User-authored edits to Character, World, Theme, Mind Map, Storyboard and other project work are valid consolidation candidates, not competing requests to modify PlotPickle's core or to republish its baseline. Resolve each edit against the **canonical question, field identity, act/scene/shot and source evidence it was intended to answer**. Identical/repeated test outputs converge into one logical contribution without erasing provenance. Compatible distinct answers and independent accepted artifacts combine. Preserve the evidence of saved approvals/locks but **do not ask the Human to approve the same work again or to pick between raw technical lists**. An edit timestamp is metadata, not a creative vote. Distinct content that is genuinely incompatible, an unproven deletion, an unresolved visual identity or a missing source cannot be silently chosen: explain the remaining uncertainty in plain language and request a *specific content decision* only if reconciliation cannot substantiate one outcome.
- **TRUTH 5 — Stable entity identity:** Merge character visuals and Shot/artifact records using proven immutable IDs. Never zip positional anonymous arrays, fabricate entity IDs, concatenate incompatible approvals, or change media lock/source identity silently.
- **TRUTH 6 — Verify answers and provenance before commit:** For each changed Character/World/Mind Map field, retrieve its canonical PlotPickle question and verify that the saved content corresponds to that field and scope, without inventing a new story answer. For images, clips, locks and narration, verify stable artifact/shot identity, source fingerprints, accepted state and readable media bytes. Identity/scope checks are deterministic; a semantic claim that prose *answers the question* requires independent, evidence-grounded assessment and must not be simulated with a string-length or timestamp heuristic. Summarize the resulting **question → retained answer** mapping, deduplications, preserved images/locks and any genuinely irreconcilable changes in ordinary language. After verification, request **one Human confirmation of the complete consolidated master**, not repeated item-by-item reapproval. Preview source IDs/revisions, proposed field changes, unresolved erasures, and media evidence; keep originals/recovery points until verified readback and confirmation.
- **TRUTH 7 — Consolidated means current:** After the account holder reviews, approves and successfully saves the verified merge, that merged copy **becomes their current authoritative Afterglow example**. Opening Afterglow normally continues that one project, and newly saved changes build on it. Superseded copies no longer clutter the ordinary choice list: they remain recoverable and may be reversibly archived only after verified readback; no deletion or second competing 'current' copy. Keep a clearly separate option to open a fresh copy of the shared provided/baseline example.
- **TRUTH 8 — Distinguish current from public:** Saving the consolidated result immediately designates it the **account's current Afterglow**, *not* a publication. `data/afterglow-packaged-current` and Git-backed media may change only after a separate explicit, appropriately authorized **Promote/Publish Afterglow example** confirmation, verified media export, reviewed GitHub PR and green gates. An ordinary user's private work must never become the distributed default merely by merging. Each user can prepare a complete promotion candidate; repository-wide publication remains permission-gated.

## Formal contracts

Let `u` be **any** authenticated PlotPickle user, `B` the trusted common packaged reference, `S(u) = {S1, ..., SN}` **all** eligible, profile-owned saved Afterglow working snapshots, with `N >= 1` and no hard-coded maximum, and `D(B,Si)` the set of supported field/entity differences, identified by canonical paths and stable entity IDs. Let `C(u)` be the proposed consolidated project and `Current(u)` the normal account-owned Afterglow shown in Library.

- `Candidates(u) = Union(D(B,Si))` for **every Si in S(u)**, not `latest(S(u))`, not `S1..S3`, and not entire-state overwrite.
- `AllEligibleSourcesIncluded(u) => ComparedSourceIDs = EligibleSavedAfterglowIDs(u)`. Any omitted version blocks a claim of completeness.
- `NonConflicting(change-set) => deterministic proposal in C`.
- `DuplicateLogicalContribution(sameCanonicalQuestion, sameMeaning, compatibleProvenance) => one retained answer plus trace of all sources`; duplicate detection must not collapse genuinely different approved story facts.
- `SupportedChange => CanonicalFieldQuestionKnown AND ScopeCorrect AND EvidenceGrounded`; a missing question/scope blocks any claim of semantic verification.
- `ComplementaryChanges AND PreservedAuthority => AutomaticReconciliation`, with one final user confirmation rather than repeated per-field approval.
- `MateriallyIncompatibleAnswers OR UnprovenDeletion OR ConflictingMediaIdentity => VisibleExplanationAndTargetedHumanDecision`; do not manufacture a question answer, choose a date as authority, or delete one side.
- `FinalHumanConfirmation => WholeMasterReview`; previous acceptance is preserved, not solicited again.
- `ConsolidationPreview => NoMutation(B,S,AccountState,GitHubPackage)`.
- `CommitAllowed(u) => HumanConfirmation(u) AND NoUnresolvedConflicts(u) AND MediaVerified(u) AND SchemaRoundTripVerified(u) AND EveryEligibleSourceAccountOwned(u)`.
- `SuccessfulConsolidationCommit(u) => Current(u) = C(u)` and all superseded saved copies are removed **only from normal opening choices**, never from recoverable account history.
- `PublishAllowed => SeparateHumanPromotionApproval AND ValidatedExport AND AllMediaGitBacked AND TestsGreen`.

**Phase 1 implementation boundary:** pure `planAfterglowConsolidation` supports a caller-supplied array of N sources without imposing a three-version limit. It exposes a proposed candidate, applied paths, conflicts, Human-review items and local asset URLs needing verification; `readyForHumanCommit: false` because it cannot authenticate, verify media or save a project on its own. **Phase 2** provides every signed-in account holder with a complete N-version preview and conflict choices, durable save/readback of one consolidated **current** Afterglow, and an uncluttered normal opener with preserved recoverable history. **Phase 3** is a *separate* appropriately authorized publication of that complete consolidated project as the **shared provided example** if and when explicitly approved.

## Question-first confirmation and duplicate-test evidence

**Human clarification from Windows UAT:** Four saved copies currently produce many entries because earlier testing can repeat accepted Character, World, Mind Map, visual and narration edits. These are not changes to the PlotPickle application core. The purpose of consolidation is **to determine whether an authored change correctly answers the original project question and belongs in the master**, not to conduct a new Human-approval exercise over every dated save.

For each change, PlotPickle must provide the canonical question, its stable field/act or visual-shot identity, the retained Human-authored answer or locked artifact, and the provenance behind that choice. Automatically deduplicate identical/repeated contributions, retain multiple complementary facts/visuals, ignore timestamps as independent story choices, and preserve all valid saved/locked evidence. Human confirmation happens **once for the intelligible finished master**, with additional targeted clarification only when supported evidence cannot safely distinguish incompatible content. Do not represent AI semantic inference as mathematical proof. The candidate cannot be saved until there is a grounded, independently verifiable question-to-answer/evidence mapping and all asset and persistence gates pass.

**Observed preview limitations:** Giant `acceptedVisualArtifactIds` lists and `graphicNovelTextApprovals` arrays must be reconciled by individual accepted artifact ID and by `(anchorRef, position)` respectively; simply choosing one whole dated list discards work. An `updatedAt` difference must travel with the corresponding authored field value and is not a separate creative question. Zero URLs returned by a candidate-only local-asset scan does **not** prove original images exist; inventory all source-media references and read the selected bytes. The current review is not yet a semantically verified master.

## Settings ownership: installation baseline, account master and official publication

**Human decision:** The consolidation and baseline controls live under **Settings → Afterglow Management**, organized into two routes. Ordinary **Library → Open Afterglow** should remain simple: continue the account's single current master or intentionally start a provided-example copy. All N dated histories belong under explicit management/recovery, not the everyday chooser.

### Route A — My Afterglow (every authenticated PlotPickle user)

- **Installed starting point:** A clean PlotPickle installation includes a verified, version-identified *provided Afterglow example*. Keep the original v9 screenplay fixture as separately immutable source evidence. Record which packaged example version established the user's installed/first-use baseline; future packaged releases cannot silently rewrite it.
- **Consolidate saved versions:** The user's account may have any number `N >= 1` of valid saved Afterglow copies. Discover every eligible account-owned copy, preview all changes, expose conflicts and missing media, and after confirmation save/read back **one authoritative current master**. Preserve historical/recovery versions without filling the everyday opening menu with them.
- **Return to Provided Baseline:** At any point the user may explicitly confirm **Return to Provided Baseline**, which creates a **fresh working copy from the verified pinned installed example** and designates it as their current starting point. The previous master and all saved history remain recoverable; reset is **not** automatic deletion, global publication, or permission to overwrite stored approvals. Label the pinned version/date clearly. If the original installed package version is unavailable, fail closed and offer available, accurately identified baselines rather than pretending to restore the exact original.
- **Resume after reset:** Future work and saved edits build on the new current account-owned working copy. Resetting one account cannot affect another account or the shared distribution.

### Route B — Publish Official Example (designated publisher only)

- A complete, approved account master may be submitted for the example **distributed in future PlotPickle installations**, but only through a distinct, explicitly authorized publication.
- **Authorization requires BOTH:** (1) a designated PlotPickle publisher identity/role from a trusted server-side source, restricted to the nominated publisher, and (2) active GitHub authorization with the exact canonical PlotPickle repository and the necessary write/PR/merge access. Generic PlotPickle accounts, generic GitHub connections, stale tokens and client-side hidden-button logic must not confer publication rights. Actual merge remains constrained by repository branch protections and required checks.
- Before release, prepare a reviewable export from the Human-approved consolidated master, check all media are copied to allowed Git-backed paths, strip profile/session/credentials and local private URLs, preserve immutable source provenance, produce a versioned manifest, and require explicit publisher confirmation. No publication on ordinary Save, Consolidate or Reset.
- A merged update to `data/afterglow-packaged-current` and packaged assets updates the canonical example shipped in **future builds/installers**. Existing installations' prior saved work or pinned reset baseline must not silently change when a new example is published.

### Observable safety invariants

- `AccountCanManage(u) => SignedIn(u) AND EverySourceOwnedBy(u)`.
- `Consolidated(u) => CurrentMaster(u) = ApprovedMergedCandidate(u)` with all eligible source IDs accounted for.
- `ResetToInstalledBaseline(u) => ExplicitUserConfirmation(u) AND PinnedBaselineVerified(u) AND NewAccountWorkingCopy(u) AND OldMasterRecoverable(u)`.
- `PrivateConsolidationOrReset(u) => NoCrossAccountEffect AND NoSharedPackageMutation`.
- `MaySubmitOfficialPublication(u) => Authenticated(u) AND DesignatedPublisher(u) AND AuthorizedGitHubCanonicalRepo(u) AND ExplicitApproval(u)`.
- `PackagedRelease => ReviewableSnapshotAndMedia AND NoPrivateSecrets AND RequiredChecksGreen AND AuthorizedMerge`.
- `PublicReleaseAtVersion(v+1) != SilentMutationOfInstalledBaselineAtVersion(v)`.

**Delivery boundary:** Phase 1 pure planner and N-version tests are merged, not an account merge UI. Phase 2 still must implement the authenticated Settings management surface, conflict/Save/Lock readback, pinned-baseline reset and clean normal opening. Phase 3 still must implement the publisher-only GitHub-backed, audited release flow. The present contract describes expected behavior, **not** existing buttons or completed functionality.

## Independent verification

Test field-complete packaging, N-version consolidation for N = 1, 2, 4, 7 and an additional arbitrary larger count (no `slice(0,3)` assumptions), non-overlapping Mind Map/World Map/Storyboard edits, identical decisions, conflicting values, attempted deletion, source identity, ordering, duplicate project IDs, and ambiguous approvals. After Phase 2, verify **each test account** can consolidate all eligible saved versions, get one current Afterglow in the everyday Library UI, reopen/restart without lost approved edits or media, and still recover older snapshots. Use live Windows account data for Human acceptance; remote CI cannot see encrypted profile data.
