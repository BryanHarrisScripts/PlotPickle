# PlotPickle visual continuity contract

Use the reviewed PlotPickle screen family as the visual source of truth.

- Matte-black / charcoal canvas with restrained warm-gold interaction and selection accents.
- Red / yellow / green are reserved for health/status semantics, not general navigation chrome.
- Editorial/typewriter character remains visible without sacrificing legibility.
- Persistent application shell and canonical workflow order remain consistent: Dashboard → Learn → Plan → Storyboard → Write → Edit → Graphic Novel → Build → Feedback → Refine → Reports/Export.
- Settings and integrations remain global utilities, visually separate from the creative workflow.
- Project identity, save state, progress and current story context should feel continuous across modules.
- The four-Act / 24-Block / 96-mini-block architecture is consistent wherever structure is relevant.
- Creative modules may change the central working surface, but should retain spacing discipline, thin borders, corner language, hierarchy and gold active-state treatment.
- Plan is the structural reference for dense creative workspaces. Learn may be richer/editorial. Write/Edit should be visually quieter. Graphic Novel and Build may be image/timeline dominant. Reports/Export is a readout/delivery workspace rather than another editor.
- No module should introduce unrelated purple/blue product chrome or a second navigation model.

Flag as WARN when the screen remains usable but visibly drifts from this family. Flag as FAIL when visual drift causes navigation ambiguity, hides current story context, makes approvals/returns unclear, or creates a materially different application shell.
