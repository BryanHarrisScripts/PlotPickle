## Architectural lock: three Factories and one Coordinator

This ordering **does not redefine** the architecture already committed to the README. The Software Factory repairs the tools, the Learning & Evolution Factory improves approved knowledge/methods, and the Game Factory builds deterministic playable worlds. The **Semantic Story Coordinator** helps stories evolve from idea to screen across established PPF production workflows; it is not a fourth Factory, new canon store, competing agent runtime or another scheduler.

Intent-centred navigation is a *routing and presentation responsibility*, not a fifth authority. Keep human editorial/canon, paid spending, private disclosure, merge policy, distribution and game-rule admission under their existing decisions. An agent may be free to pursue a delegated purpose without interrupting every approved substep, but it may never broaden its own authorization. One common pathway: **Human intent → grounded evidence / preparation → relevant Human decision → approved execution → verifiable receipt**.

Retain the README distinctions between **BELIEVED**, **PROPOSED**, **EXECUTED**, and **INDEPENDENTLY VERIFIED**. Never label a mock UI, green unit test or code-only merged PR as independently accepted physical device behavior, verified media, or creative canon.

## Operating principles and dependencies

1. **Strict priorities, not a rigid waterfall.** Security is first; storage is second and active; Windows reliability supports all future autonomy. Small cross-cutting work may proceed when needed to verify the current priority. The Coordinator and Game Factory can each make bounded, individually verified progress without waiting for the entire preceding Factory to be 'complete'. Brotherly Love remains a continuous real-world acceptance fixture even before its end-to-end deliverable is scheduled.
2. **Execution pipeline:** Build → Test → Fix → Independently Verify (specific source SHA, real Windows / app / browser / provider as applicable) → PR → Merge *only when green and permitted* → Next admitted task. CI success alone is not a real Windows product gate; apply truthful statuses **IMPLEMENTED**, **OWNER-UAT-REQUIRED**, **NOT-IMPLEMENTED**, **BLOCKED**, **PARKED**.
3. **Protect user data:** PPF/Library, creative assets, project media, locks, approved versions, credentials, model weights, original source and immutable evidence are protected. Storage reclamation requires complete per-root measurement, Git worktree registration, reference/process/task checks, compact receipt preservation, local dry-run and owner-confirmed exact batches; never delete on age alone. A storage preflight is not a durable disk reservation.
4. **Known storage baseline at roadmap lock:** Owner Windows observed **65/65 candidate PR stage folders registered as Git worktrees**, **126 total Git worktrees**. A bounded metadata sample measured **13.44 GiB apparent/logical bytes in only 24/65 stage folders**. Free space fell from ~27.44 GB after earlier recovery to ~15 GB later, but no exact attribution or physical reclaimable-byte count is proven. The new PR-stage brake (#3283 merged) caps **new** retained candidate stages to 3 with 8 GiB headroom; it does **not** remove existing stages, and may block engineering until verified retirement. The complete storage design (#3284 merged) is now **ACTIVE implementation direction** by this new decision, superseding its October 24 hold status. This decision does not authorize automatic deletion.
5. **Security first:** Four independent npm graphs (root, `.pi/npm`, `.pi/managed`, `tools/hunk-review`); treat security issue #3279's screenshot alert count as historical until GitHub/current dependency evidence confirms outcomes. Correct reachable versions with explicit dependency provenance and independent checks; don't close on a PR title alone.
6. **No parallel stacks:** Reuse existing PPF, agent/Skill/runtime, provider contracts, evidence/verification, GitHub/Factory queue, BUZZ and approved UI components. Software Factory, Learning, Game and Coordinator are interoperable responsibilities, not independent apps.
7. **Bounded cohorts:** Deliver one verifiable vertical slice at a time. Maintain the existing **seven campaign** ownership map in #3274; the twelve ordered priorities are a cross-campaign **execution order**, not a replacement for its 56-issue historical register. Do not resurrect superseded implementation or close open source issues without verifying their acceptance criteria.
8. **READMEs and normative truth:** Before proposing a subsystem change, review related README constraints and existing relevant developer briefs/contracts, including the approved White Paper testing obligations. When a roadmap recommendation conflicts with source-backed canon, surface the discrepancy explicitly and amend via a separately reviewed PR rather than silently rewriting history.
