# Scope and evidence limits

This package requires no publisher-hosted service and makes no network calls.
It uses only the execution and file capabilities actually available to the
user. It does not provide those capabilities or establish their billing terms.
No author account, factory tunnel, secret or fixed user file ID is bundled.

The supplied project export is the observation source. A valid checksum proves
which file was inspected, not who authored it, whether the local application
saved it correctly, or whether it is the latest project revision. Missing
revision/identity, a changed checksum or incomplete raw structure blocks an
inspection rather than being silently repaired into a successful result.

Four Acts, twelve Sequences, twenty-four Blocks, ninety-six Mini-Blocks and
twenty-five planned Shots per Mini-Block are the canonical planning scaffold.
The 3-second Shot and 75-second Mini-Block are planning targets. They do not
prove a film's runtime, a finished render or frame accuracy of actual media.

Shot source passages belong to a Mini-Block unless individually mapped by a
separate verified owner. A stored image reference or accepted ID is metadata.
This reader does not open referenced image URLs, verify image bytes, infer
voice/narration approval, or certify playable video. Exported localhost paths
will generally need separately supplied media for cloud viewing.

The prototype does not edit or write PPF state. Editing, media registration,
Save/Lock parity, concurrent-version handling, durable asset storage and actual
new-conversation recovery need further implementation and acceptance.

The package has not been tested on Go. Running the bundled reader in one
Plus Work conversation proves only execution there. Installing it does not
establish public-directory approval or support across all plans and surfaces.
