# #3142 — One-shot owner-authorized coding worker: bounded source edit

October 25, 2026. This is the first executable source-mutation slice toward the independent engineering dispatcher. It is deliberately separate from the existing read-only supervisor and the one-shot OBSERVE gateway.

## Delegation and authority

The local Windows operator must provision a private, single-use `engineering-edit-once` grant in `%LOCALAPPDATA%/PlotPickle/engineering-team/conversation-gateway/owner-coding-grants/<grantId>.json`. Its exact fields are validated by `validateCodingGrant`: a 32-character random grant ID; issue number; exact clean MAIN commit; one `scripts/engineering-team/**/*.mjs` file and its SHA-256 content digest; one `tests/issue-*.test.mjs` focused-test identity; a bounded owner-specified objective; model identifier; output-token cap; expiration within one hour; `maxRequests: 1`; and exact consent `AUTHORIZE_ONE_ENGINEERING_SOURCE_EDIT`. This narrow local grant is **not** created by a remote issue, browser, ChatGPT tool, AI response, or this worker. Credentials come only from the local `OPENAI_API_KEY` environment and never enter GitHub.

The only native entry point is `node scripts/engineering-team/gateway/authorized-coding-once.mjs --once <grantId>`, run from the owner Windows checkout. Clean MAIN and trusted Git origin are established through the existing `gatewayAppSource`. This CLI is **not** mounted as a remotely invocable MCP tool or attached to the observer supervisor. Importing the module has no side effects.

## Bounded edit and durable result

The worker checks one target file, its digest, and a named existing focused test before reserving the grant in a private write-once receipt. It then creates an isolated detached Git worktree at the exact source commit and a grant-specific local branch, makes **one** Responses API request with `store:false` and no tools, accepts at most one unique exact text replacement in the granted file, performs only non-executing syntax/diff checks, and commits the edit locally with Git hooks disabled. Model-authored text cannot choose a command, path, test, branch, merge, network destination, or credential.

Generated code is **not run on the owner's Windows host**. The focused-test identity travels with the receipt but execution belongs to a subsequent independent, isolated CI verifier. A successful worker returns `LOCAL_COMMIT_PREPARED`, not “issue fixed”: the result contains the branch, exact commit, focused-test path, and explicit `focusedTestExecuted:false`, `pullRequestCreated:false`, `independentVerification:false` and `automaticMergeAuthorized:false`.

A write-once stage sentinel and a serialized private stage-budget lock admit at most three retained coding stages before a grant is consumed. Existing stages, including uncertain or crashed attempts, count toward that budget; unknown entries or an orphaned lock fail closed and require owner inspection rather than age-based deletion. A reservation is fsynced before external requests or source mutation; duplicate delivery cannot replay it. If a model request, edit, Git command, receipt or local operation becomes uncertain, the stage stays for inspection and the worker fails closed. No worktree is automatically deleted, no blocked Factory reservation is replayed, no Pi dispatcher is started and no existing task or app is restarted.


## Draft PR publication slice (not yet unattended)

The existing inert `authorized-pr-publish-once.mjs` Windows CLI accepts `--once <publicationId>` only. It requires a **second**, locally provisioned owner grant in `owner-publication-grants/<publicationId>.json`; the coding grant alone cannot authorize GitHub writes. Exact v1 fields: `schemaVersion:1`, `kind:"draft-pr-publish-once"`, distinct 32-hex `publicationId` and coding `grantId`, `issueNumber`, clean MAIN `sourceHead`, `localCommit`, deterministic `branch` (`engineering/<issue>-<grantId>`), `targetPath`, expiry within one hour, `maxRequests:1`, and `consent:"AUTHORIZE_ONE_DRAFT_ENGINEERING_PR"`. A scoped `PLOTPICKLE_GITHUB_PUBLISH_TOKEN` is supplied only through the owner's local environment; it must have the minimum repository Git contents and pull-request write permissions. Never put tokens in GitHub, issues, prompts or receipts.

Publication verifies the original edit grant, exact prepared result, clean isolated staged Git worktree, one changed path, exact source parent, local tree and blob. It uses fixed GitHub Git-data REST endpoints, not shell-driven `git push`: verify remote MAIN; upload the committed source blob and verify its Git SHA; build and verify the exact Git tree; create a remote commit with the approved parent/tree; create a new deterministic branch ref; recheck MAIN; then create a **draft** PR with a fixed, non-model-authored title/body and explicit pending CI/Windows verification. The remote commit SHA may differ from the local commit SHA; the durable result records both identities and the verified identical tree. No force-update, arbitrary shell, merge, test execution or implicit queue admission is allowed.

The first external request is preceded by a write-once private reservation. Every uncertain response remains permanently non-replayable; later recovery may only reconcile read-only evidence before a separately authorized new attempt. Fixture tests exercise wrong local parent/path, missing token, remote MAIN drift, exact tree/blob mapping, draft PR metadata, duplicate delivery and uncertain branch publication. These fixtures are not proof of live GitHub publication or owner-host Windows acceptance. The Software Factory startup path does **not** currently launch the coding worker or publisher. Revocable supervisor startup, STOP/Pause, independent CI/Windows verifier receipts and a genuine owner-granted publication cycle remain separate acceptance steps.
