# Developer brief — #2395 Storyboard Act, Scene and Beat layout

## Human intent

Storyboard follows Outline's written structure. The first screen should have full-width header, context and footer and navigate by Act 1–4. An Act shows six Blocks, a Block shows four Mini-Blocks, and a selected Mini-Block opens the next visual layer: mapped Scenes, authored Beats and a sequence of storyboard stills. The Storyboard should show more than one image per Mini-Block. The 120-minute example gives 75 nominal seconds per Mini-Block and 25 possible three-second positions, but those positions are a planning scale, not a demand for 25 images or 25 videos. Shots and clips belong to later Previs and Production work.

## Existing owners

Use canonical 24/96 addresses, imported screenplay Scene projection, Sequence Director Beat projection where authored, and existing visual-artifact candidate/Keep authority. Preserve the Storyboard editorial review and deep links. Storyboard has no new canon, beat assignment or timing authority in this slice. Source provenance remains inspectable without leading the visual page.

## Acceptance

1. The Storyboard header, context section and footer fill their containing surface; redundant Project label and duplicate first-address banner are removed.
2. Four Act tabs precede six Block choices for the selected Act. Existing Block and Mini-Block deep links open the matching Act and address. Selection continues through the Skin V1 preproduction context.
3. Each Block shows its four canonical Mini-Block anchors. Selecting one shows only real mapped Scenes, real authored Beats when present, existing candidate or kept visuals, and 25 clearly optional visual positions for the 120-minute example. Empty evidence stays explicit, without fake Scene, Beat or image records.
4. Written screenplay and provenance remain in collapsed inspection, while the initial view is visual. The Storyboard frame count and three-second render slots are not conflated.

## Verification

Focused Storyboard, visual density, semantic projection and navigation regressions; focused UAT contract and production build in GitHub CI. The 25 positions are an interface layout affordance, not authored timing or a fixed visual count.
