# #2828 — Packaged Afterglow Storyboard media contract

## Outcome

Repair the real Afterglow media path that remained outside #2827's synthetic `/api/local-ai/assets/...` fixture.

The canonical PlotPickle project contract already accepts two safe visual-media classes:

- Human/generated local media under `/api/local-ai/assets/...`
- immutable packaged example media under `/assets/library/examples/...`

The promoted Afterglow example intentionally rewrites generated media into the second class. Runtime Save, narration, FFrames handoff, common media/reference helpers and native H3 had independently narrowed that contract back to generated-local files only. As a result, a valid current Afterglow Storyboard image could render in the project and still fail Save, narration or image-to-video preparation.

## Confirmed cause

This was a cross-layer contract divergence, not proof of logout and not absence of the Storyboard artifact.

The project normalizer accepted packaged example images while:

- Storyboard explicit Save required `/api/local-ai/assets/`.
- Storyboard/Previs narration contact-sheet preparation required the same local-only prefix.
- common media readers resolved only the profile-local asset directory.
- optional FFrames handoffs used the local-only resolver.
- native H3 image/reference uploads assumed every image lived in the profile-local asset directory.

The #2827 rendered proof used a synthetic generated-local image, so those narrower guards were never exercised.

## Repair

`core/media/visual-asset-url.ts` now owns the shared supported visual URL classification. It admits only the two existing canonical PlotPickle visual namespaces; it does not broaden support to arbitrary `/assets/` paths.

`build/media-storage-common.ts` adds a server-side project image resolver that maps:

- generated local media to the Human profile asset directory;
- packaged example media to PlotPickle's shipped `public/assets/library/examples` directory.

Resolution rejects encoded, traversal, query, fragment, backslash, empty and unsupported-extension paths and verifies the resolved file remains inside the owning root.

Storyboard Save uses the shared supported-media rule and continues to wait for the same durable acknowledgement introduced by #2827. Save/Lock/Delete feedback is attached to the affected Shot instead of being visible only below the full 25-Shot grid.

Narration accepts same-origin supported PlotPickle Storyboard media and still rejects unrelated asset paths. Existing authentication and CSRF requirements are unchanged.

Media/reference helpers, Previs/Timeline FFrames handoffs and native H3 image/reference input use the shared safe project-image resolver. Video outputs remain profile-local generated assets. Native H3 source-video input remains local-generated-only.

## Regression proof

`tests/issue-2828-packaged-storyboard-media-contract.test.mjs` reads the committed Afterglow manifest and snapshot, selects an actual packaged Storyboard artifact, and proves:

- the committed package URL is recognized by the canonical contract;
- its image bytes resolve only inside the packaged-example root;
- unsafe traversal/encoded paths are rejected;
- it can be converted into a media-provider video/reference source;
- the actual Storyboard Save and Lock/Unlock handlers retain the explicit Save marker without duplicating media;
- the actual narration contact-sheet function reads the same packaged image instead of failing its URL guard;
- unrelated `/assets/` paths remain rejected.

The existing #2821 Save/session regression remains registered and aligned with the shared helper.

## Security and data invariants

- Packaged repository image bytes remain immutable.
- Saving a packaged image records story-state intent; it does not copy the image into the Human asset vault.
- No arbitrary filesystem path, arbitrary public asset URL or remote HTTP image is admitted.
- Authentication, CSRF, provider authorization and billing acknowledgement are unchanged.
- No paid provider job is generated by this engineering proof.
